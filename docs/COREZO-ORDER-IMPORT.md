# COREZO（金沢楽座）注文メールの受注取込

COREZOのECモール「金沢楽座」に注文が入ると、`support@corezo.co.jp` から
注文確認メールが届きます。これを人の手を介さずに受注へ登録します。

```
COREZO → Gmail（support@corezo.co.jp）
   │  ① Apps Script（1時間おき）がメール本文を共有ドライブ「COREZO」フォルダに保存
   ▼
共有ドライブ COREZO/ ──（Googleドライブ パソコン版で同期）──▶ サーバーのMac
   │  ② Mac（1時間おき）が新しい本文を読み取り、注文メールなら受注に登録
   ▼
COREZO/取込済・要確認・未分類 に仕分け ＋ Slackで通知
   │
   ▼
③ 毎朝8時の ship-docs が、その受注の送り状（Webゆうパックプリント）と
   納品書（マネーフォワード）を登録する（docs/SHIP-DOCS-UPLOAD.md）
```

- カナカンのFAXと違い**OCRは要りません**（本文がそのまま読めるため）。Tesseractも不要です。
- Gmailの確認は1時間おき、Mac側も1時間おきです。注文から受注登録まで最大で約2時間かかります。
- **印刷と発送は人が行います。**

## フォルダの使い分け

| フォルダ | 入るもの | 人がすること |
|---|---|---|
| `COREZO/`（直下） | 届いたばかりのメール本文 | なし（次の確認で仕分けられる） |
| `COREZO/取込済/` | 受注に登録したメール。名前は `注文日_注文番号.txt` | なし |
| `COREZO/要確認/` | 登録できなかった注文メールと、**COREZOからの連絡メール** | 中身を見て、受注画面から手で登録・修正 |
| `COREZO/未分類/` | COREZOと関係のないメールと、**他社の商品だけの注文メール** | 中身を見て、要らなければ `不要/` へ移す |
| `COREZO/不要/` | 要らないメール | なし（置いてから30日で自動削除） |

`要確認/` の原因（商品マスタに当たる商品が無いなど）を直したあとで、ファイルを
`COREZO/` 直下に戻すと、次の確認でもう一度取り込みます。

## 登録される内容

| 受注の項目 | メールのどこから |
|---|---|
| 受注日 | メールの受信日（本文に注文日が無いため） |
| 得意先 | **金沢楽座**（COREZO）。得意先マスタから名前で引く |
| 商品 | **「商品名」だけ**で商品マスタと突合（白／金・能登／長野・度数・容量・パウチ等がすべてそろう1件）。メールの「商品コード」はCOREZO側の番号なので見ない |
| 本数 | ご注文商品明細の「数量」 |
| 売価 | **上代 × 得意先マスタの掛け率**（卸8掛け） |
| 送料 | 1注文あたり **909円（税抜）** |
| 納品希望日 | 「お届け日」。「指定なし」なら空 |
| お届け先 | 「◎お届け先」の節を**そのまま** `delivery_address` に入れる |
| 備考 | `COREZO注文番号：141709`（二重登録の防止に使うので消さない） |

### 金額について

**メールに載っている金額は読みません。** あれは消費者が払った額（例 4,630円）で、
COREZOから当社に入る額ではないためです。売価は受注画面で手入力するときと同じく、
上代と得意先マスタの掛け率から出します。

送料は取り決めでは**1,000円（税込）**ですが、システムに入れる値は**909円（税抜）**です。
請求額の式（`src/services/invoiceAmount.js`）が `(売価 + 送料) × 1.1` で送料にも税を掛けるため、
1,000円をそのまま入れると1,100円ぶん請求してしまいます。909円で入れると、

```
(2,640 + 909) × 1.1 = 3,904円   ← 取り決めどおりの額
```

になります。送料の二重課税そのものは別件の課題です（直すときはここも併せて見直します）。

### お届け先をそのまま入れる理由

送り状CSV（`csvExportService.exportYuPack`）は `delivery_address` を
`utils/shippingAddress.parseShippingAddress` で分解します。あちらは
「お名前：」「郵便番号：」「〒」「様」「お届け日：」「指定なし」「18時～20時」を
すでに解釈できるので、**組み立て直さずそのまま渡すのが一番崩れません。**

## 配送先変更などの連絡メール

`support@corezo.co.jp` からは、注文確認のほかに「注文番号◯◯ 配送先住所変更について」
といった連絡も届きます。これらは**自動では直しません**（2026-10-20 決定）。
送り状をすでに作ったあとだと機械では直せず、紙と記録が食い違ったまま気づけないためです。

`要確認/` に置き、Slackで知らせます。受注画面から人が直してください。

## 使い方

```bash
# まず登録も移動もせずに動かしてみる
npm run corezo-inbox -- --dry-run

# 問題なければ取り込む
npm run corezo-inbox
```

| 表示 | 意味 |
|---|---|
| `registered` | 受注に登録しました |
| `dry_run` | 登録内容の確認のみ（`--dry-run`） |
| `duplicate` | 同じ注文番号の受注がすでにある（取消済みも含む） |
| `notice` | COREZOからの連絡メール。登録せず「要確認」へ |
| `needs_review` | 登録できなかった。理由と候補をSlackに出します |
| `not_corezo` | COREZOと関係のないメール。「未分類」へ |
| `not_ours` | 他社の商品だけの注文。登録せず「未分類」へ |

## 設定手順（最初の1回だけ）

### ① 共有ドライブに「COREZO」フォルダを作る

共有ドライブ「NOTO Naorai」の直下に `COREZO` を作り、URLからフォルダIDを控えます
（`https://drive.google.com/drive/folders/【ここがID】`）。

### ② Apps Script（Gmail → 共有ドライブ）

1. https://script.google.com を **sugai@naorai.co** で開き、「新しいプロジェクト」を作る（名前は「COREZO保存」など）
2. `gas/corezo-saver/Code.gs` の中身を貼り付ける
3. 先頭の `COREZO_FOLDER_ID` を①で控えたIDに書き換えて保存する
4. 関数の選択欄で **`setup`** を選び「実行」。権限の確認が出たら許可する
   - これで1時間おきの実行が登録され、1回目がすぐ動きます（**過去14日分**を保存します）
5. Gmailで、COREZOのメールに `COREZO保存済` ラベルが付いていれば成功です

### ③ Mac（共有ドライブ → 受注登録）

`.env` に保存先を書き足します（場所は `ls ~/Library/CloudStorage/` で確認）。

```bash
COREZO_INBOX_DIR=/Users/YOUR_NAME/Library/CloudStorage/GoogleDrive-sugai@naorai.co/共有ドライブ/（共有ドライブ名）/COREZO
```

試しに `npm run corezo-inbox -- --dry-run` を動かし、登録予定の内容が正しいことを
確認してから、`launchd` に1時間おきの実行を登録します（やり方は
[FAX-AUTO-IMPORT.md](FAX-AUTO-IMPORT.md) の `jp.noto-naorai.fax-inbox.plist` と同じ要領で、
`ProgramArguments` を `scripts/corezo-inbox.js` に変えたものを作ります）。

## 気をつけること

- **COREZOのメールには他社の商品も載ります。** 商品名に「浄酎」「JOCHU」が無い商品は
  他社の商品として外し、当社の商品だけを登録します（外した商品はSlackに注意として出ます）。
  他社の商品だけの注文は登録せず `未分類/` に置きます。
- **商品は商品名で決めます。** メールの「【石川・能登】能登浄酎 JOCHU White(和スピリッツ)35度 300ml」
  から 白・能登・35度・300ml を読み取り、商品マスタ「JOCHU White NOTO 35 300ml」に当てます。
  度数・容量が同じ長野の商品（浄酎白長野35 300）と取り違えないよう、産地まで見ます。
  浄酎なのに1件に決まらない商品は登録せず `要確認/` に置くので、受注画面から手で登録してください。
- **得意先マスタに掛け率が無いと、売価が上代のままになります。** 登録はしますが、
  Slackに注意を出します。
- **1注文を複数のお届け先に分ける注文は登録しません**（送り状が1枚しか出ないため）。
  要確認に置くので、受注画面から分けて登録してください。
- **複数商品の注文は、送り状の段ボールサイズが自動では決まりません。**
  段ボール対応表が「商品 × 本数」の1対1のためで、COREZOに限らず元からの制約です。
  ship-docs の結果に「未解決」として出るので、画面で箱を選んでください。
