# 過去データの移行手順

現行スプレッドシートの中身を、新しいシステムへ移します。
実データを通した予行演習は済んでいます（全21シート・約1,500行が投入でき、
外部キーの不整合0件で完走することを確認済み）。

---

## 1. 準備

```bash
cd ~/noto-inventory-system
git pull origin main
npm install
```

### 必ずバックアップを取る

**これが唯一の戻す手段です。**

```bash
mkdir -p backups
sqlite3 db/database.sqlite ".backup backups/before-migration-$(date +%Y%m%d).sqlite"
```

戻すとき:

```bash
cp backups/before-migration-YYYYMMDD.sqlite db/database.sqlite
```

**ファイル名は `customer_list.csv` にしてください**（シート名が何であっても、
この名前で置けば読み込みます）。この表を使わない場合は、置かなければ飛ばされます。

| シート | ファイル名 |

拡張子が `.csv` のままでも中身はCSVでなくなります。
そうなっていたら、ファイル名を添えて止めるので直せます。

## 3. まず投入せずに確認する

```bash
node scripts/migrate-from-sheets.js --dry-run
```

読み込み件数と、直すべき点が表示されます。実際には書き込みません。

**一度でも本番投入したあとは `--reset` も付けてください。**

```bash
node scripts/migrate-from-sheets.js --dry-run --reset
```

`--dry-run` は台帳を消しません。前回投入した行が残ったまま流すと、
受注番号や履歴IDがぶつかって `UNIQUE constraint failed` が並びます。
**シートにもデータにも問題が無いのにエラーが出る**ので、原因の調査が空回りします。
台帳にデータがある状態で `--reset` を付けずに流すと、その旨を先に知らせます。

### レポートを見る

`scripts/migration-report/` に次のファイルが出ます。

| ファイル | 中身 |
|---|---|
| `summary.json` | シートごとの読込・投入・更新・スキップの件数 |
| `errors.csv` | 取り込めなかった行と、その理由 |
| `unmatched-names.csv` | 名前でマスタを引けなかった値と、**似ている名前の候補** |
| `aliases-suggested.json` | 候補が1つに絞れたものだけを集めた、そのまま使える補正表 |
| `master-updates.csv` | 既にあったマスタの行を、シートの内容でどう書き換えたか |
| `skipped-rows.csv` | 取り込まずに飛ばした行と、その理由 |
| `orphan-masters.csv` | シートのどの行にも対応しなくなったマスタ行 |

`unmatched-names.csv` に行が残っていると、`--dry-run` はそこで止まります。

### 飛ばした行を見る

サマリーの「スキップ」に数えられた行は、`skipped-rows.csv` に理由つきで出ます。

```
sheet,rowNumber,reason,hint
顧客リスト,48,得意先名が空欄です,
顧客リスト,52,得意先マスタに無い名前です,まだ登録していない酒販店
```

`hint` はシートで探すための手がかりです（行番号だけだと、並べ替えたシートでは
見つけられないため）。**エラーとは分けています。** `errors.csv` は直すべき失敗、
`skipped-rows.csv` は意図して取り込まなかった行です。

### シートから消したマスタ行を見る

**マスタは消しません。** シートから商品を1行外しても、データベースには残り、
受注の商品の選択肢にも出続けます。そういう行は `orphan-masters.csv` に出します。

```
table,code,name,reason
商品,P003,終売にした商品,シートに同じIDも同じ名前もありません（シートから消したか、IDと名前の両方を変えた行）
```

**出るだけで、移行は止まりません。** 受注が紐付いている商品は消せないので、
消すかどうかは見て決めてください。消すなら `/masters.html` から、
残すならそのままで構いません。

なお**IDと名前を同時に変えると別の行になります**（古い行が取り残しとして出て、
新しい行が追加される）。名前だけ変えたいときは、ID列は変えないでください。

### 表記ゆれを直す

不一致は「シートの書き方」と「マスタに登録されている名前」が違うだけ、という
ものがほとんどです。`scripts/data/aliases.json` に対応表を書いて埋めます。

**まず `aliases-suggested.json` を見てください。** 名前の似かたから機械が当てた案が
入っています。中身を確かめて、正しければ `scripts/data/aliases.json` にコピーします。

```json
{
  "得意先": {
    "のと空港セレンブティ": "のと空港セレンディピティ",
    "道の駅千里浜": "道の駅のと千里浜"
  }
}
```

候補が複数あって絞れなかったもの（カナカンのように支店が並ぶ場合）は
ここに入りません。`unmatched-names.csv` の「候補1〜3」の列を見て、
自分で決めて書き足してください。

```
sheet,column,rawValue,normalizedValue,候補1,候補2,候補3
顧客リスト,得意先,カナカン,カナカン,カナカン酒類石川,カナカン酒類七尾,カナカン酒類高岡
```

#### 書き方の決まり

- **左が「シートに書かれている表記」、右が「マスタに登録されている名前」。**
  左右が同じものは何もしません（書くと警告が出ます）。
  右辺にマスタに無い名前を書いても効きません。
- **全角と半角の違い、括弧の全角半角、前後の空白は自動で吸収します。**
  `地域未来創造（コレゾ）` → `地域未来創造(コレゾ)` のような対応は書く必要がありません。
- **外側のキーは `unmatched-names.csv` の `column` 列と同じ文字にします。**
  シートごとに違うので注意してください。

  | どのシートの不一致か | キー |
  |---|---|
  | 得意先マスタ | `得意先名` |
  | 顧客リスト（連絡先の表） | `得意先` |
  | 受注リスト・委託販売実績報告 | `得意先名` |
  | 商品を引く列 | `商品名称` / `商品` |
  | 資材を引く列 | `資材名` / `資材名称` |
  | タンクを引く列 | `受入元` / `払出先` / `元容器ID` |

  どれか分からないときは `unmatched-names.csv` の `column` をそのまま使えば確実です。
- `_` で始まるキー（`_説明` など）は読み飛ばすので、覚え書きを置けます。

#### まず、標準テキストで保存してください（Mac）

**テキストエディットの既定はリッチテキストです。** 新規ファイルに貼って保存すると、
拡張子が `.json` でも中身はリッチテキスト書類（RTF）になり、JSONとして読めません。

テキストエディットで開いて **「フォーマット」→「標準テキストにする」（⇧⌘T）** を
選んでから保存してください。ターミナルなら次でも直せます。

```bash
textutil -convert txt -output scripts/data/aliases.json scripts/data/aliases.json
```

VS Code など、標準テキストしか扱わないエディタを使うならこの心配はありません。

#### 手で書くとつまずきやすいところ

JSONは書き方に厳しいので、次の3つを踏みやすいです。**どれも自動で直すので、
そのままでも読めます。**

```json
    "株式会社升々": "浄酎升々",     ← 閉じ括弧の直前のカンマ（本来は不要）
　　"__ignore__": {                ← 行頭の全角スペース
    "近江町松本": “株式会社松本"    ← 全角の引用符（“ ” ‘ ’）
```

全角の引用符は、エディタや変換の設定で勝手に入ることがあります。
直したときは**何行目の何を直したか**を出すので、意図した文字か確かめてください。

```
[aliases.json] 11行目の全角の引用符（“ U+201C）を直して読み込みました。
  意図した文字か確認してください: "近江町松本": “株式会社松本"
```

それでも読めないときは、**何行目の何文字目か**を指して止まります。

```
scripts/data/aliases.json の11行目・18文字目でつまずきました:
    "近江町松本": “株式会社松本"
                  ^
  全角の引用符（“ U+201C）です。半角の " に直してください。
```

#### 書いた内容が効くかは、実行時に教えます

右辺に**マスタに無い名前**を書いてしまうと、書いたのに何も起きません。
外側のキーの取り違え（`得意先名` と `得意先`）も同じです。
どちらも実行したときに名指しします。

```
[aliases.json] 「得意先名」の「近江町松本」→「株式会社松本」は、
  右辺がマスタに登録されていないので効きません。似ている名前: 松本 / 松本重工業
[aliases.json] 「得意先マスタ名」はどの列にも当たらないので、中身は使われません。
  使える列: 得意先名 / 得意先 / 商品名 / …
```

#### マスタに無いのが正しい値

廃番になった商品を指すレシピ行のように、マスタに無いのが正しい行があります。
`__ignore__` に書いておくと、不一致として数えず静かに飛ばします。

```json
{
  "__ignore__": {
    "商品名称": ["白30ml サンプル用(旧)"]
  }
}
```

ひな形は `scripts/data/aliases.example.json` にあります。

直したら 3 に戻ってやり直します。**エラーと不一致がゼロになるまで繰り返してください。**

## 4. 本番投入

```bash
node scripts/migrate-from-sheets.js
```

**流し直すときは必ず `--reset` を付けてください。**

```bash
node scripts/migrate-from-sheets.js --reset
```

付けないと、受注・蒸留明細・容器変動などが二重に入り、在庫が倍になります。
`--reset` は台帳とトランザクションだけを消し、マスタは残します。

どうしても一部の不一致を残したまま進めたいときだけ `--allow-partial` を付けます。
不一致があっても止まらずに投入します。

**ただし、残したまま進めると穴が空きます。**

| 不一致の場所 | どうなるか |
|---|---|
| 得意先・商品・資材など、その行に必須の名前 | その行は**投入されません**（`errors.csv` に出ます） |
| タンクの列（`受入元` `払出先` `元容器ID`） | 行は入りますが、**タンクの欄が空**のまま入ります |

タンクの欄が空で入ると、その分の液がどのタンクにも紐付かず、
タンクモニターの残量が合わなくなります。
**タンクの不一致だけは、`--allow-partial` で流す前に必ず片付けてください。**
タンクは名称（`テナー9`）でも容器ID（`Q-009`）でも引けるので、
`aliases.json` にはどちらを書いても構いません。

## 5. 答え合わせ

```bash
node scripts/verify-migration.js
```

シートのモニターと、こちらが台帳から計算した在庫を並べて、差のある行だけ出します。

**差は出ます。それが普通です。**
現行シートのモニターは、GASが操作のたびにセルへ足し引きしていた**別建ての数字**で、
台帳から計算し直したものではありません（`updateStockMonitor_` がセルに直接
`現在値 + 増減` を書き込む作り）。長く運用するうちに台帳とずれます。
新システムは台帳から計算するので、両者は一致しません。

差を消す方法は**棚卸**です。`/stocktaking.html` で実際に数えた数を入れると、
差が調整の記録として台帳に残り、以降は計算値と実物が一致します。

## 移行のあとにやること：支店を持つ会社の「本店」を設定する

カナカンのように支店がある会社は、シートでは支店ごとに別々の得意先として並んでいます。
**どの会社が親子かはシートに書かれていないので、移行スクリプトでは判断できません。**
移行後に画面から設定してください。

### なぜ必要か

得意先マスタのカナカンは6支店あり、支払いサイトの入り方がバラバラです。

| 顧客ID | 得意先名 | 支払いサイト |
|---|---|---|
| C0008 | カナカン酒類石川 | 翌月末日 |
| C0009 | カナカン酒類七尾 | 翌月末日 |
| C0010 | カナカン酒類高岡 | 翌々月末日 |
| C0101 | カナカン酒類富山 | **空欄** |
| C0105 | カナカン酒類福井 | **空欄** |
| C0151 | カナカン業本七尾 | 翌月末日 |

**空欄の支店は、そのままだと受注を入れても入金予定日が出ません。**
本店を設定すると、本店の「翌々月末日」を引き継いで出るようになります。

### 手順

1. `/masters.html` の得意先タブで、**本店の行を新しく登録する**（例: 「カナカン」）
   - 掛率・支払いサイト・請求書送付期日・請求先の担当者を入れる
   - 住所は本社のもの
2. 各支店の行を「編集」し、**「本店（親の得意先）」で本店を選ぶ**
3. 支店の掛率・支払いサイトのうち、本店と同じでよいものは**空欄にする**
   （空欄なら本店から引き継ぎます。支店に値が入っていれば支店が優先されます）

引き継いでいる値は編集画面に出ます。

```
本店から引き継いでいる値: 支払いサイト（月数）=2（カナカン） / 支払いサイト（日）=末日（カナカン） /
請求書送付期日=月初に業務課へ郵送（カナカン） / 請求書の担当者=業務課（カナカン）
```

住所・電話・配送先は支店ごとに違うので**引き継ぎません**。

設定すると、受注登録で「カナカン」と検索したときに6支店すべてが出て、
それぞれに「本店: カナカン」と併記されます。

得意先マスタのCSVに **「本店」列**（別名: 親得意先／本社）を足しておけば、
取り込みのときに名前で紐付けることもできます。本店の行がCSVの後ろにあっても構いません。

## 移行で起きること（知っておいてほしいこと）

### 伝票番号を振り直します

現行シートでは、**同じ番号が2つの意味で使われていました**。

| 組 | 実データでの一致件数 |
|---|---|
| 受注番号（D）と 蒸留ID（D） | 37件 |
| 原酒受払ID（M）と 資材履歴ID（M） | 73件 |

移行時に、受注番号は `D2605-0001` → `O2605-0001`、
原酒受払IDは `M2603-0001` → `R2603-0001` に振り直します。
蒸留IDの `D` と資材履歴IDの `M` はその記号で正しいので、そのままです。

**元の番号は残ります。** `legacy_order_no` / `legacy_lot_code` に入るので、
シートとの突き合わせはできます。

副産物として採番の連続性も直ります。振り直さないと、2608に新規受注を入れたとき
`O2608-0001` から始まって過去の `D2608-0006` と番号が並んで見えてしまいます。

### 同じ受注番号に別の得意先が入っている行があります

実データに6件ありました（`D2606-0017` が「ナオライEC」と「カナカン酒類石川」など）。
番号の付け間違いと思われますが、勝手に消さず明細2行目として残します。
移行後に受注一覧の「編集」で直してください。

### 蒸留記録の3件がシートに無い

浄酎容器変動履歴が `D2606-0025` `D2606-0026` `D2606-0027` の継足を記録しているのに、
蒸留記録シートにその行がありません。容器の動きは残し、蒸留への紐付けは空にします。

### 重複した履歴IDには枝番が付きます

同じ商品履歴ID・資材履歴IDを持つ行が実データにあります（採番の競合と、
まったく同じ行の二重記録）。番号はひとつしか持てないので、
2件目以降は `M2607-0013-2` のように枝番を付けて**行は残します**。
在庫の動きを1件も落とさないためです。`errors.csv` に一覧が出ます。

### 原酒マスタは銘柄名ではなく「原酒ID」で持ちます

同じ銘柄でもロットが違えば度数が違います。実データにも

| 原酒ID | 銘柄 | 度数 |
|---|---|---|
| `toriya-BYR6-L1` | 浄酎用池月 | 18.3 |
| `toriya-BYR6-L2` | 浄酎用池月 | 18.8 |

のように、同じ銘柄名の別ロットが並んでいます。
以前は銘柄名で一意にしていたため片方しか入らず、流し直すたびに度数が
入れ替わっていました。度数は蒸留の計算に効くので、**原酒IDで1行ずつ持ちます**。

**同じ原酒IDが2行以上あると、`-L1` `-L2` を付けて分けます。**
実データの `unzan-BYR6` が2行あったので、`unzan-BYR6-L1` `unzan-BYR6-L2` になります。
どちらがどのロットかを固定したいときは、シート側のID列に直接書いてください
（シートに書いてあればそのまま使います）。付け替えは `errors.csv` に出ます。

原料受払記録の「原酒スペック」は、**銘柄名でも原酒IDでも**書けます。
同じ銘柄名の行が2つ以上あるときは、名前だけでは決められないので紐付けず、
不一致として報告します。その場合は原酒IDで書いてください。

### 時刻の無い日付は 00:00 で入ります

蒸留記録の投入開始時刻と、残渣回収記録の回収時刻はシートに時刻がありません。
`00:00` で埋めます。24時間経過アラートの起点になる値ですが、
移行分は既に完了しているので影響しません。

### マスタは、既にある行もシートの内容で更新します

テスト入力で作った得意先・商品が、シートに同じ名前であれば**シートの内容で更新されます**。
支払いサイトが空のままだった得意先も、これで正しい値になります。
何をどう書き換えたかは `scripts/migration-report/master-updates.csv` に
`sheet,name,column,before,after` で出るので、後から確かめられます。

`summary.json` と画面の表示では「更新」として数えます。

```
得意先マスタ: 読込156 / 投入0 / 更新156 / スキップ0
```

**ただし、次の列は既にある行には当てません。**

| 当てない列 | どのマスタ | なぜ |
|---|---|---|
| `初期在庫数` | 資材マスタ | 在庫計算の起点。動かすと現在の在庫が変わる |
| `初期商品在庫数` / `初期仕掛品在庫数` | 商品マスタ | 同上 |
| `初期在庫量` / `現在液量(L)` | タンクマスタ | 同上 |
| `初期在庫量` / `現在在庫量` | 原酒マスタ | 同上 |
| 内部ID（`uid`） | すべて | 付け替えると他の表との紐付けが切れる |
| `本店`（`parent_id`） | 得意先マスタ | 移行後に画面で設定した内容を消さないため |

#### 名前を直したいとき（改名）

行を見つける鍵は**ID列**（`顧客ID` `商品ID` `資材ID` `容器ID` `酒蔵ID` `ID`）です。
**ID列を変えずに名前だけ直して流し直せば、改名として反映されます。**
受注や台帳の紐付けは切れません。

```
得意先マスタ,株式会社松本,name,松本,株式会社松本   ← master-updates.csv
```

逆に、**ID列も一緒に変えると別の行になります。** 旧名の行が受注を抱えたまま残り、
同じ取引先が2行になるので注意してください。

ID列が空のままの行は、これまで通り名前で照合します。

`顧客ID` `商品ID` のような番号の列は、**シート側が空なら今の値を残します**
（`COALESCE`）。空で上書きして番号を失わないためです。

なお、マスタのシート（得意先マスタ・商品マスタなど）で**空になっている列は、
空で更新します**。「シートが正」という前提なので、シートで消した値はこちらでも消えます。
残したい値はシートに書いてから流してください。

例外は**顧客リスト**（連絡先の表）です。こちらは得意先マスタの後から
メール・電話・郵便番号だけを足しに行く表なので、**空欄は今の値を残します**。
連絡先を消したいときは画面から編集してください。

「次回todo/課題」は営業メモとして入りますが、**同じ内容が既にあれば入れ直しません**。
流し直しても同じ課題が積み上がらないようにしています。
